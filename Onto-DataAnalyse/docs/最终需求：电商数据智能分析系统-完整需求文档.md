## 一、项目概述

### 1.1 系统定位

本系统是一个**本体模型驱动的电商经营数据智能分析演示系统**，以 B/S 架构实现，无需登录，无权限控制，面向演示场景。

系统通过引入本体模型作为业务语义中间层，连接电商原始数据库与 AI 推理引擎，实现从自然语言需求输入到可视化数据分析报告的全流程自动化。所有 AI 推理调用真实的 DeepSeek API，不提供 Mock 降级模式。

### 1.2 四阶段工作流

```
阶段一：需求探索
用户上传预置的演示 DB Schema Markdown 文件 + 分析需求描述
AI 解析输出结构化需求确认文档
（上传功能为演示流程，实际始终使用内置演示数据库）

      ↓ 确认后

阶段二：本体模型构建
AI 基于需求 + 本体建模规范（ontology_modeling_framework）生成完整本体模型
生成 M1/M2/M3/M4/M_Metric 共五个独立 YAML 文件，存储到 models/ 目录
（M5 角色模型不实现）
可视化一：动态演进的知识图谱（含完整实体关系连线）
可视化二：字段级数据库映射（可视化连线）

      ↓ 确认后

阶段三：预设场景执行
三个预设场景：经营异常分析 / GMV 分析 / 客户流失分析
执行流程：预定义 SQL 采集数据 → 统计计算 → 真实 AI 推理（流式展示）

      ↓ 随时进入

阶段四：AI 对话与报告输出
自然语言输入，匹配预设场景
输出：国际咨询公司风格的完整可视化分析报告
（文字摘要 + ECharts 图表 + 数据表格 + 推理结论 + 置信度）
```

#### 2.2.2 知识图谱动态演进效果（核心功能）

**重要设计要求**：知识图谱不是等待全部模型生成完成后一次性展示，而是随着每个模型的生成实时动态更新，用户能看到图谱从空白逐步丰富的演进过程。

**动态演进步骤**：

```
Step 1（M1 实体识别时）：
→ 首先出现各个实体节点（大圆，无连线）
→ 节点以弹入动画出现（缩放 0→1，duration 300ms）

Step 2（M1 关系定义时）：
→ 实体间连线依次出现（逐条绘制，每条 200ms）
→ 订单→订单明细（组合关系，红色实线）
→ 订单明细→商品SKU（关联，蓝色）
→ 商品SKU→商品SPU→商品类目（层级关系）
→ 用户→订单（多对一）
→ 用户→用户行为（聚合）
→ 店铺→商品（关联）
→ 订单→支付记录、退款记录、物流记录（组合）
→ 订单→优惠券使用（关联）
→ 营销活动→优惠券（聚合）
→ 访问会话→页面访问记录（组合）
→ 用户→访问会话（聚合）

Step 3（M2 行为模型生成时）：
→ 行为节点（橙色小圆）飞入，连接到所属实体

Step 4（M3 规则模型生成时）：
→ 规则节点（金色小圆）飞入，连接到被引用的行为

Step 5（M4 场景模型生成时）：
→ 场景节点（蓝色中圆）飞入，连接到相关行为

Step 6（M_Metric 指标模型生成时）：
→ 指标节点（青绿色菱形）飞入，连接到依赖实体
→ 指标同时连接到其计算规则
```

每一步都有流畅的布局重计算（D3 force simulation 重新运行），整体图谱在演进过程中保持视觉平衡。

**图谱生成算法要求**：

后端在解析 M1 YAML 时，必须从以下位置提取关系：

```python
def extract_relations_from_m1(yaml_content: dict) -> list[dict]:
    """
    从 M1 对象模型 YAML 中提取所有关系，用于图谱连线
    关系来源：
    1. entities[].attributes[] 中 type=Reference 的字段
       → 该实体与 refEntity 之间有关联关系
    2. relations[] 列表中显式定义的关系
       → 直接使用 sourceEntity、targetEntity、type
    3. entities[].constraints[] 中 FOREIGN_KEY 类型
       → 补充隐式关联关系
    """
    edges = []
    
    # 来源1：属性中的 Reference 类型
    for entity in yaml_content.get('entities', []):
        for attr in entity.get('attributes', []):
            if attr.get('type') == 'Reference':
                edges.append({
                    'source': entity['id'],
                    'target': attr['refEntity'],
                    'type': 'association',
                    'label': attr.get('label', ''),
                    'cardinality': attr.get('refCardinality', '')
                })
    
    # 来源2：显式关系定义
    for rel in yaml_content.get('relations', []):
        edges.append({
            'source': rel['sourceEntity'],
            'target': rel['targetEntity'],
            'type': rel['type'],          # COMPOSITION/AGGREGATION/ASSOCIATION
            'label': rel.get('targetRole', ''),
            'cardinality': rel.get('targetCardinality', '')
        })
    
    return edges
```

## 三、本体建模规范补充：M_Metric 指标模型

### 3.1 M_Metric YAML 文件格式规范

M_Metric 是对现有本体建模规范（ontology_modeling_framework M1-M4）的扩展，专门用于描述数据分析指标。

**文件格式定义**：

```yaml
# M_Metric 指标模型元文件
# 文件名：m_metric_model.yaml
model_type: METRIC
version: "1.0"
domain: "电商经营分析"

metrics:
  - id: String                    # 指标唯一标识，格式：MTR-{Domain}-{Seq}
                                  # Domain: TXN(交易)/TFC(流量)/USR(用户)/PRD(商品)/MKT(营销)/SCM(供链)
    name: String                  # 指标中文名称
    alias: String                 # 英文标识（camelCase）
    description: String           # 指标业务含义说明
    formula_description: String   # 计算口径的自然语言描述（非SQL）
    
    computation_type: Enum        # 计算类型
                                  # SQL_COMPUTE: 确定性SQL聚合计算
                                  # STAT_ALGO: 统计算法（同环比/异常检测/RFM等）
                                  # LLM_REASONING: AI语义推理
    
    depends_on_entities:          # 依赖的M1实体ID列表
      - EntityRef                 # 如 ENT-ORD-001
    
    rule_refs:                    # 依赖的M3规则ID列表（口径规则）
      - RuleRef                   # 如 RULE-MTR-001
    
    sql_template: String          # SQL计算模板（computation_type=SQL_COMPUTE时必填）
                                  # 支持参数化：{date_start} {date_end} {granularity}
    
    stat_algorithm: String        # 统计算法名称（computation_type=STAT_ALGO时必填）
                                  # 可选值：mom_yoy/anomaly_3sigma/rfm_score/abc_classification
    
    supported_grains:             # 支持的统计粒度
      - Enum                      # DAY/WEEK/MONTH/QUARTER/YEAR
    
    supported_dimensions:         # 可拆分分析维度
      - String                    # 如 shop/category/channel/region
    
    default_visualization: Enum   # 默认图表类型
                                  # line/bar/pie/scatter/heatmap/funnel/gauge
    
    unit: String                  # 计量单位，如 "元" "%" "个" "天"
    
    tags:                         # 分类标签
      - String                    # 如 core/growth/efficiency/quality
```

### 4.3 D3.js 力导向图配置

```javascript
// Force Simulation 配置
const simulation = d3.forceSimulation(nodes)
  .force('link', d3.forceLink(edges)
    .id(d => d.id)
    .distance(d => {
      // 根据边类型设置不同的理想距离
      const distances = {
        composition: 80,
        aggregation: 90,
        association: 120,
        dependency: 100,
        event_chain: 110,
        rule_ref: 90,
        metric_dep: 130,
        scenario_call: 100,
      };
      return distances[d.type] || 100;
    })
    .strength(d => {
      const strengths = {
        composition: 0.8,
        aggregation: 0.6,
        association: 0.4,
        dependency: 0.3,
        metric_dep: 0.2,
      };
      return strengths[d.type] || 0.4;
    })
  )
  .force('charge', d3.forceManyBody()
    .strength(d => {
      // 节点越大排斥力越强
      const radii = { entity: -300, behavior: -150, rule: -120, metric: -100 };
      return radii[d.type] || -150;
    })
  )
  .force('center', d3.forceCenter(width / 2, height / 2))
  .force('collision', d3.forceCollide(d => {
    const r = { entity: 40, behavior: 28, rule: 26, scenario: 30, metric: 26 };
    return r[d.type] || 30;
  }))
  .force('x', d3.forceX(width / 2).strength(0.05))
  .force('y', d3.forceY(height / 2).strength(0.05))
  .alphaDecay(0.02)
  .velocityDecay(0.4);
```

### 4.4 动态节点添加算法

```javascript
/**
 * 动态向图谱中添加节点和边（生成过程中逐步调用）
 * 每次调用后重启 simulation，图谱平滑过渡到新布局
 */
function addNodesAndEdges(newNodes, newEdges) {
  // 1. 新节点在画布中央附近随机初始化位置
  newNodes.forEach(node => {
    node.x = width / 2 + (Math.random() - 0.5) * 100;
    node.y = height / 2 + (Math.random() - 0.5) * 100;
    node.vx = 0;
    node.vy = 0;
  });
  
  // 2. 追加到现有数组
  nodes.push(...newNodes);
  edges.push(...newEdges);
  
  // 3. 新节点以缩放动画出现（transform: scale 0→1）
  // 在 D3 enter 选择中添加 transition
  
  // 4. 重启 simulation，alpha 设为较高值让布局重新计算
  simulation.nodes(nodes);
  simulation.force('link').links(edges);
  simulation.alpha(0.5).restart();
}
```

### 4.5 图谱交互功能

- **节点拖拽**：拖拽后固定位置（fx/fy），双击取消固定
- **节点点击**：右侧抽屉展示该节点的完整 YAML 内容（语法高亮）
- **节点悬停**：Tooltip 显示节点类型、名称、描述；关联边高亮
- **边悬停**：显示关系类型和基数说明 Tooltip
- **顶部过滤器**：按节点类型筛选，非选中类型节点淡出（opacity: 0.15）
- **滚轮缩放**：d3.zoom，缩放范围 0.3x ~ 3x
- **画布平移**：鼠标拖拽空白区域
- **重置布局**：按钮触发 alpha(0.8).restart()，回到居中分布

client = OpenAI(

def stream_completion(messages, model=None, temperature=0.1, max_tokens=4096):
    """流式调用 DeepSeek API"""
    response = client.chat.completions.create(
        model=model or settings.DEEPSEEK_MODEL,
        messages=messages,
        stream=True,
        temperature=temperature,
        max_tokens=max_tokens
    )
    for chunk in response:
        if chunk.choices[0].delta.content:
            yield chunk.choices[0].delta.content

### 11.3 SQL 安全校验

```python
FORBIDDEN_KEYWORDS = [
    'INSERT', 'UPDATE', 'DELETE', 'DROP', 'CREATE',
    'ALTER', 'TRUNCATE', 'REPLACE', 'ATTACH', 'PRAGMA'
]

def validate_and_prepare_sql(sql: str) -> tuple[bool, str, str]:
    """
    返回：(is_valid, prepared_sql, error_message)
    """
    sql_stripped = sql.strip()
    sql_upper = sql_stripped.upper()

    if not sql_upper.startswith('SELECT'):
        return False, '', '只允许 SELECT 查询'

    for kw in FORBIDDEN_KEYWORDS:
        if f' {kw} ' in f' {sql_upper} ':
            return False, '', f'禁止使用 {kw} 操作'

    # 强制追加 LIMIT
    if 'LIMIT' not in sql_upper:
        sql_stripped = sql_stripped.rstrip(';') + ' LIMIT 10000'

    return True, sql_stripped, ''
```

## 附录：关键技术约束汇总

| 约束项 | 规范 |
|--------|------|
| 数字准确性 | LLM 不生成数字，全部数字来自 SQL 或统计算法，LLM 只做引用和推理 |
| SQL 安全 | 仅 SELECT，强制 LIMIT，禁止 DDL/DML，通过 `sql_validator.py` 校验 |
| API 降级 | 不提供 Mock 降级，API 不可用时前端显示明确错误提示 |
| 本体文件存储 | 生成的 YAML 文件落盘到 `backend/models/{project_id}/` |
| 知识图谱关系 | 必须从 M1 YAML 的 relations 和 Reference 类型属性中提取边，不能缺失 |
| 图谱动态演进 | 每生成一个模型就立即推送图谱更新事件，前端实时添加节点和边 |
| 映射可视化 | 字段级别的连线，颜色对应置信度，支持点击查看详情 |
| 无登录 | 系统无认证，无权限控制，直接访问所有功能 |
| 演示数据固定 | 演示 DB 使用 `random.seed(42)` 生成，结果可重复 |
| 报告风格 | 参考国际咨询公司风格，图文并茂，置信度透明，建议可执行 |
