# 人工智能知识体系

> 人工智能是研究如何让软件系统感知、学习、推理、生成、决策并与人协作的技术体系。本文按 KSB_V3.3 构建三层知识结构，重点放在软件、算法、AI 工程和大模型；硬件、边缘设备、具身智能等内容作为必要边界提及但不展开。本文用于学习、教学和工程梳理，不构成产品选型或安全合规结论。

## 一、顶层知识：领域主干（思维导图式展开）
> 查看对应图表：[knowledge_top.html](knowledge_top.html)  
> 读图方式：根节点为“人工智能”，左右展开 8 个一级主干；默认展开到三级，先看软件算法主线，再看工程化、评估安全和应用软件。

### 1.1 AI 基础与问题定义
- 定义：AI 基础关注智能任务如何被形式化为输入、输出、目标函数、约束和评价指标。
- 核心要点：AI 系统通常由数据、模型、目标、推理过程和反馈循环组成；不同任务对应不同学习范式和系统边界。
- 可验证实例：图像分类可定义为输入图片、输出类别、以准确率或 F1 作为指标的监督学习任务。
- 关键子主题：任务建模、搜索推理、知识表示、概率统计、优化基础、评价指标。

### 1.2 机器学习算法
- 定义：机器学习让模型从数据中学习规律，而不是完全依赖人工规则。
- 核心要点：监督学习解决标注样本映射，无监督学习发现结构，强化学习通过奖励优化策略；泛化能力取决于数据、模型容量、正则化和评估方式。
- 可验证实例：用历史贷款样本训练信用风险模型，预测新申请人的违约概率。
- 关键子主题：监督学习、无监督学习、强化学习、特征工程、模型选择、集成学习。

### 1.3 深度学习与神经网络
- 定义：深度学习用多层神经网络自动学习表示，适合处理图像、语音、文本和多模态数据。
- 核心要点：反向传播和梯度下降是训练核心；CNN 擅长局部空间结构，RNN/Transformer 擅长序列与上下文，扩散模型擅长生成式建模。
- 可验证实例：Transformer 的自注意力机制可以并行建模长文本中的词元依赖，是现代大模型的基础。
- 关键子主题：反向传播、优化器、CNN、RNN、Transformer、扩散模型、表示学习。

### 1.4 大模型与生成式 AI
- 定义：大模型通常指通过大规模数据和算力训练、具备通用生成与迁移能力的基础模型。
- 核心要点：预训练获得通用能力，指令微调增强任务服从，对齐训练改善人类偏好，RAG 和工具调用把模型连接到外部知识和系统。
- 可验证实例：一个客服助手可用 RAG 从企业知识库检索政策，再让 LLM 生成回答并附带来源。
- 关键子主题：基础模型、LLM、Token、Embedding、预训练、SFT、RLHF/RLAIF、RAG、Agent、提示工程。

### 1.5 AI 软件工程与 MLOps
- 定义：AI 软件工程关注如何把模型变成可靠、可维护、可部署、可监控的软件系统。
- 核心要点：AI 系统不仅是模型，还包括数据管道、训练管道、服务接口、评估、监控、回滚和治理；LLMOps 进一步处理 Prompt、上下文、工具和反馈数据。
- 可验证实例：生产模型上线后需要监控延迟、成本、漂移、错误率和用户反馈，超过阈值时触发回滚或再训练。
- 关键子主题：数据管道、训练流水线、模型注册、推理服务、特征库、监控、A/B 测试、LLMOps。

### 1.6 数据、评估与 AI 安全
- 定义：数据、评估与安全决定 AI 系统是否可靠、公平、可解释、可控和合规。
- 核心要点：数据质量影响上限；离线评测不等于线上效果；大模型还需关注幻觉、越狱、隐私泄露、偏见、版权和模型滥用。
- 可验证实例：同一个 LLM 在通用问答分数高，不代表在医疗、金融等高风险场景可直接上线。
- 关键子主题：数据治理、标注质量、基准评测、红队测试、可解释性、公平性、隐私、安全对齐。

### 1.7 AI 应用软件与产品形态
- 定义：AI 应用软件把模型能力封装进可用产品，包括搜索、推荐、办公助手、代码助手、客服、数据分析和行业应用。
- 核心要点：产品价值来自工作流嵌入，而不是单点模型能力；用户体验、权限控制、反馈闭环和成本管理同样重要。
- 可验证实例：代码助手需要理解仓库上下文、生成补丁、运行测试，并把结果反馈给开发者。
- 关键子主题：智能搜索、推荐系统、Copilot、客服机器人、代码生成、BI 分析、行业应用。

### 1.8 硬件边缘与具身智能（边界）
- 定义：硬件、边缘 AI 和具身智能为 AI 软件提供算力平台、低延迟执行环境和物理世界交互能力。
- 核心要点：GPU/TPU/NPU 影响训练和推理成本；边缘部署关注延迟、功耗和隐私；具身智能涉及机器人、感知、控制和仿真。
- 可验证实例：手机端语音识别模型需在有限功耗下完成低延迟推理。
- 关键子主题：GPU/TPU/NPU、推理加速、量化、边缘 AI、机器人、仿真、传感器融合。

## 二、中间层知识：多维矩阵（知识矩阵式展开）
> 查看对应图表：[knowledge_middle.html](knowledge_middle.html)

### 2.1 维度定义
- 维度①：知识模块。取值：基础建模、机器学习、深度学习、大模型、AI 工程、评估安全、应用软件、硬件具身。
- 维度②：工程场景。取值：研究学习、模型训练、系统开发、产品应用、治理合规。
- 维度③：难度层级。取值：入门、进阶、高级。

### 2.2 矩阵解读
- 重点交叉：大模型 × 系统开发包含 Prompt、RAG、Agent、工具调用、上下文管理，是当前 AI 软件工程的核心交叉区。
- 重点交叉：AI 工程 × 产品应用包含推理服务、监控、A/B 测试和成本优化，是模型落地成软件产品的关键路径。
- 重点交叉：评估安全 × 治理合规包含红队测试、隐私保护、公平性和模型风险管理，是高风险场景上线前的必要关卡。
- 盲区标注：硬件与具身智能只做边界提及，若要深入机器人、芯片或自动驾驶，应另建专门知识体系。

## 三、最底层知识：知识网络（图谱式展开）
> 查看对应图表：[knowledge_bottom.html](knowledge_bottom.html)  
> 结构化数据：[knowledge_graph.json](knowledge_graph.json) / [knowledge_graph.csv](knowledge_graph.csv)

### 3.1 核心节点群（按主干分类）
- AI 基础与问题定义：AI 任务、搜索、知识表示、概率统计、优化、损失函数、评价指标、数据分布。
- 机器学习算法：监督学习、无监督学习、强化学习、特征工程、线性模型、决策树、集成学习、交叉验证。
- 深度学习与神经网络：神经网络、反向传播、梯度下降、CNN、RNN、Transformer、自注意力、扩散模型。
- 大模型与生成式 AI：基础模型、LLM、Token、Embedding、预训练、指令微调、对齐训练、RAG、Agent、工具调用。
- AI 软件工程与 MLOps：数据管道、训练流水线、模型注册、推理服务、特征库、模型监控、漂移检测、LLMOps。
- 数据评估与安全：数据治理、标注质量、基准测试、红队测试、幻觉、可解释性、公平性、隐私保护、AI 安全。
- AI 应用软件：智能搜索、推荐系统、代码助手、客服机器人、文档助手、数据分析助手、行业 AI 应用。
- 硬件边缘与具身智能：GPU/TPU/NPU、量化、推理加速、边缘 AI、机器人、仿真环境、传感器融合。

### 3.2 关联类型与网络特征
- 高频关系：依赖关系占主导，说明 AI 学习路径强依赖数学基础、数据、模型训练和评估闭环。
- 关键枢纽节点：Transformer、自注意力、Embedding、预训练、RAG、推理服务、数据治理、模型监控、AI 安全。
- 网络特征：软件与算法主干最密集；硬件具身节点与推理加速、边缘 AI、机器人应用相连，但不作为本文展开重点。

### 3.3 推荐学习路径
- 速成路线（约 20 小时）：AI 任务 → 监督学习 → 神经网络 → Transformer → LLM → Prompt → RAG → 推理服务 → 基础评估。前置依赖：Python、线性代数和概率基础。
- 工程落地路线（约 50 小时）：数据治理 → 数据管道 → 训练流水线 → 模型注册 → 推理服务 → 监控 → 漂移检测 → LLMOps → 红队测试。前置依赖：后端开发、数据库、容器和 API 基础。
- 大模型路线（约 40 小时）：Token → Embedding → Transformer → 预训练 → 指令微调 → 对齐训练 → RAG → Agent → 工具调用 → 安全评估。前置依赖：深度学习和 NLP 基础。
