# Documentation Guidelines

本目录保存当前事实、架构决策、反向工程证据和 Wayfinder 规划。文档必须使用直接、可验证的语言。

## 文档分类

- `wayfinder/`：决策地图与票据。地图只做索引，详细决策只存在于对应票据的 Resolution。
- `meta-model/`：DPA 反向工程事实、推断、假设、覆盖率和一致性报告。
- `architecture/`：当前已确认架构、数据流、时序、部署和安全边界。
- `adr/`：难以撤销且经过真实权衡的架构决策。

不要把计划写进架构现状文档，不要把实现细节写进 `CONTEXT.md`，不要把票据答案复制到地图。

## 写作标准

- 中文正文使用统一术语；源码符号、路径、配置键、URL、表名和稳定 ID 保持原文。
- 每段只表达一个主题；标题应能独立说明内容。
- 区分已确认事实、推断、假设和建议，不把未来设计写成当前实现。
- 引用代码时提供仓库、revision、路径、符号和行号；引用模型时提供领域、稳定 ID 和版本。
- 安全材料只记录凭据的来源和管理方式，不记录真实值。
- 图与正文使用相同稳定 ID；图是投影，不成为第二事实源。
- 当前状态文档只描述当前有效结论；历史原因放 ADR 或已关闭票据。
- 修改链接、文件名或稳定 ID 时同步更新所有引用。

## Wayfinder 操作

- Wayfinder 地图、工作包标题、Task 正文、验收标准和解决记录统一使用中文；源码符号、路径、协议字段、命令和稳定 ID 保持原文。
- `tickets/` 下的每个文件是一个工作包，工作包内继续拆分为多个可独立执行和验证的 Task。
- 每个 Task 必须包含达成目标、输入、执行步骤、产出物和验证方式；必要时补充前置 Task 和边界。
- 当前 Copilot 主 Agent 是工作包与 Task 的默认执行者，必须自行完成可通过仓库、工具和测试获得的工作。
- 主 Agent 应按需调用 codebase-memory MCP、专业 Skill 和并行子 Agent；子 Agent 的输出必须由主 Agent 复核、整合和验收。
- 只有业务语义裁决、安全风险接受、真实环境授权和发布批准等必须由人负责的事项，才进入人工门禁。
- 领取工作包前先填写 `assignee`。
- 每个会话最多关闭一个工作包，但可完成该工作包内多个满足依赖的 Task。
- Task 只有在产出物落库且验证完成后才能从 `[ ]` 改为 `[x]`。
- “解决记录”只记录最终答案、关键取舍、验证结果和产生的资产链接。
- 关闭工作包后才向地图“已完成决策”添加一行摘要。
- 新工作包先创建，再在第二步添加 `blocked_by`。
- 超出“最终目的地”的内容进入“不在本路线图范围内”，尚需决策但仍在范围内的内容进入“尚未明确”。

## 检查

文档修改至少检查：

```powershell
git diff --check
```

若项目后续提供链接、Schema 或 Wayfinder 校验脚本，使用仓库定义的命令，不自行引入新的文档工具。
