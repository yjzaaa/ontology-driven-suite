# 本地 Wayfinder 任务跟踪规则

总地图：[DPA 本体建模与运行工作台实施规格路线图](map.md)

MasterData 试点范围：[MasterDataPROnlineApprovalController / SubtableType](masterdata-scope.md)

## 层级定义

- **地图**：描述最终目的地、不可违反的边界、工作包依赖和整体完成判定。
- **工作包**：`tickets/` 下的 Markdown 文件，聚合一个可独立评审的决策领域。
- **Task**：工作包内最小可领取执行单元，必须产生明确资产并可独立验证。
- **解决记录**：工作包关闭时追加的最终结论、取舍、证据和产出链接。

工作包不是 Task。仅写一个待回答问题不能视为完成了任务拆分。

## 执行责任

- 本路线图中的所有工作包和 Task 默认由当前 Copilot 主 Agent 执行。
- 主 Agent 负责读取代码和文档、调用 MCP/Skill、编写规格与样例、制作 PoC、运行验证并更新 Task 状态。
- 对彼此独立且不会修改同一文件的工作，可由主 Agent 启动多个子 Agent 并行执行。
- 子 Agent 是执行资源，不是最终责任人；主 Agent 必须检查其产出并完成整体一致性验收。
- 用户不需要代替 Agent 收集资料、编写文档、运行命令或维护工作包。
- 需要 DPA 技术负责人、领域专家、安全负责人或发布审批人的场景，应由 Agent 先准备证据、选项和建议，再请求人工作出不可自动化的裁决。

## Task 必填结构

每个 Task 必须包含：

1. **达成目标**：完成后新增了什么确定性能力或结论。
2. **输入**：执行前必须读取的代码、文档、模型、样例或上游产出。
3. **执行步骤**：为得到结果必须完成的具体动作。
4. **产出物**：仓库中可定位、可复查的文件、图、Schema、样例或报告。
5. **验证方式**：可重复执行的检查、评审场景、测试命令或通过条件。

建议同时写明：

- **前置 Task**：同一工作包内必须先完成的 Task。
- **边界**：明确该 Task 不负责什么，防止范围持续膨胀。

## 状态与领取

- 工作包使用 `status: open|closed`。
- 空 `assignee:` 表示尚未领取；主 Agent 开始执行时默认填写 `copilot-agent`。
- `blocked_by` 保存前置工作包文件名。
- 同一工作包内的 Task 使用复选框跟踪：`[ ]` 未完成，`[x]` 已完成。
- 领取工作包前先填写 `assignee`；一个会话最多关闭一个工作包。
- 允许一次执行同一工作包内多个相关 Task，但不得绕过其前置 Task。

## 完成与关闭

Task 只有同时满足以下条件才可勾选完成：

- 产出物已经写入约定位置；
- 验证方式已经执行；
- 验证结果已记录，且不存在未处理的阻断问题；
- 新发现的重大问题已经建立后续 Task 或工作包。

工作包只有同时满足以下条件才可关闭：

- 所有标记为必需的 Task 已完成；
- 工作包验收标准全部通过；
- 文件末尾已追加 `## 解决记录`；
- `status` 已改为 `closed`；
- 地图的“已完成决策”已追加一行摘要和链接。

## 依赖维护

- 新工作包先创建文件，再在第二次编辑中添加 `blocked_by`，避免悬空引用。
- 工作包间依赖只记录在 front matter 和地图依赖表中。
- 工作包内依赖写在 Task 的“前置 Task”中。
- 修改文件名、Task ID 或稳定模型 ID 时，必须同步更新全部引用。

## 验证要求

每次修改 Wayfinder 文档至少执行：

```powershell
git diff --check
```

还必须检查：

- 所有 `blocked_by` 文件存在；
- 所有相对 Markdown 链接有效；
- 每个 Task 都包含“达成目标”和“验证方式”；
- 工作包标题、正文、产出说明和验收标准使用中文；
- 源码符号、协议字段、路径、命令和稳定 ID 保持原文。
